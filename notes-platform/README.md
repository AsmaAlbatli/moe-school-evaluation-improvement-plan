# منصة الملاحظات والمتابعة

منصة عربية RTL لإدارة ملاحظات الفريق ومتابعتها: لوحة مؤشرات، تصنيف حسب المجال والأولوية والحالة، توصيات وإجراءات تصحيحية، مسؤول وتاريخ استهداف، سجل إنشاء وتحديث، وبحث وتصفية متقدمة — مع تخزين سحابي كامل عبر **Supabase PostgreSQL** بدل `localStorage`.

## أبرز المزايا

- **لوحة مؤشرات فورية:** إجمالي الملاحظات، الجديدة، قيد المعالجة، والمغلقة، مع نسب مئوية.
- **إضافة وتعديل وحذف:** نموذج كامل مع تحقق من المدخلات، رسائل نجاح/خطأ، ومؤشرات تحميل.
- **تصنيف منظم:** المجال، الأولوية (منخفضة/متوسطة/عالية/حرجة)، والحالة (جديدة/قيد المعالجة/مغلقة).
- **توصيات وإجراءات تصحيحية:** حقول مخصصة لكل ملاحظة، ولوحة «توصيات المتابعة» التي ترصد المتأخرات، الأولويات الحرجة، والنواقص.
- **مسؤول وتاريخ استهداف:** متابعة الالتزام وإبراز المتأخرات وتلك التي تستحق خلال ٧ أيام.
- **بحث وتصفية:** نص حر، الحالة، الأولوية، المجال، المسؤول، الاستحقاق، نواقص المتابعة، وتاريخ الإنشاء.
- **سجل زمني:** تاريخ الإنشاء، آخر تحديث، تاريخ الإغلاق، ومنشئ الملاحظة.
- **مزامنة سحابية:** Supabase Auth + جدول `notes` واحد للفريق، مع RLS.
- **تحديث مباشر:** اشتراك Realtime اختياري (يُفعّل من المخطط) لتحديث القائمة عند تغيير أعضاء الفريق.
- **وضع معاينة:** `?demo=1` لاختبار الواجهة ببيانات تجريبية في الذاكرة دون Supabase ودون حفظ.

## التشغيل السريع

### 1) إعداد Supabase

1. أنشئ مشروعًا في [Supabase](https://supabase.com/dashboard).
2. افتح **SQL Editor** ونفّذ محتوى:
   ```
   notes-platform/supabase/schema.sql
   ```
3. من **Project Settings ← API** انسخ:
   - **Project URL**
   - **anon / publishable key**
4. افتح:
   ```
   notes-platform/assets/js/supabase-config.js
   ```
   وأضف القيمتين:
   ```js
   window.NOTES_SUPABASE = {
     url: "https://YOUR-PROJECT.supabase.co",
     anonKey: "YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY",
     allowSignup: true
   };
   ```

> **لا تضع أبدًا** مفتاح `service_role` أو `sb_secret_...` في ملفات المتصفح. المنصة ترفض العمل إذا اكتشفت مفتاحًا سريًا. الحماية الحقيقية تأتي من سياسات RLS.

### 2) إنشاء حسابات الفريق

- من شاشة الدخول، اضغط **حساب جديد** وأنشئ حسابًا لكل عضو.
- بعد إنشاء الحسابات، يُنصح بإيقاف **Allow new users to sign up** من:
  `Authentication ← Providers ← Email` أو إعدادات Auth.
- اجعل `allowSignup: false` في `supabase-config.js` لإخفاء تبويب «حساب جديد».
- جميع الحسابات المسجّلة ترى ملاحظات الفريق وتستطيع إضافتها وتعديلها وحذفها وفق سياسات RLS.

**روابط المصادقة (مهمة لتأكيد البريد):**

من `Authentication ← URL Configuration` أضف عنوان المنصة إلى:

- **Site URL**: مثل `http://localhost:8080/notes-platform/`
- **Redirect URLs**: أضف الصيغتين:
  `http://localhost:8080/notes-platform/`
  و`http://localhost:8080/notes-platform/index.html`
  وأضف رابط النشر الفعلي لاحقًا (مثل `https://USERNAME.github.io/REPO/notes-platform/index.html`).

### 3) تشغيل المنصة

المنصة تحتاج رابط `http(s)`؛ لا تعمل مصادقة Supabase عند فتح الملف مباشرة عبر `file://`.

**من جذر المستودع:**

```bash
python -m http.server 8080
```

ثم افتح:

```
http://localhost:8080/notes-platform/
```

أو استخدم إضافة **Live Server** في VS Code.

**معاينة بدون إعداد:**

```
http://localhost:8080/notes-platform/index.html?demo=1
```

وضع المعاينة لا يتصل بـ Supabase ولا يحفظ أي بيانات بعد إغلاق الصفحة.

**دخول تجريبي مؤقت (للمعاينة فقط):**

- البريد: `demo@school.edu.sa`
- كلمة المرور: `Demo@2026`

هذا الحساب عام ومكشوف في كود الواجهة، ومخصص للعرض فقط. لا تستخدمه مع بيانات حقيقية؛ الحماية الفعلية تأتي من Supabase Auth وRLS بعد ربط المشروع.

## مخطط قاعدة البيانات

الجدول الرئيسي: `public.notes`

| الحقل | النوع | الوصف |
|---|---|---|
| `id` | uuid | المفتاح الأساسي |
| `title` | text | عنوان الملاحظة (1–160) |
| `description` | text | الوصف (حتى 5000) |
| `domain` | text | المجال (قيمة من قائمة محددة) |
| `priority` | text | منخفضة / متوسطة / عالية / حرجة |
| `status` | text | جديدة / قيد المعالجة / مغلقة |
| `recommendation` | text | التوصية (حتى 4000) |
| `corrective_action` | text | الإجراء التصحيحي (حتى 4000) |
| `owner_name` | text | المسؤول عن المتابعة |
| `target_date` | date | التاريخ المستهدف |
| `created_by` | uuid | منشئ الملاحظة (ثابت) |
| `created_by_name` | text | اسم المنشئ وقت الإنشاء |
| `created_at` | timestamptz | تاريخ الإنشاء (ثابت) |
| `updated_at` | timestamptz | آخر تحديث (تلقائي) |
| `closed_at` | timestamptz | تاريخ الإغلاق (تلقائي) |

**المحفز `notes_before_write`:**

- يضبط `updated_at` تلقائيًا عند كل تعديل.
- يضبط `closed_at` عند الانتقال إلى «مغلقة»، ويمسحه عند إعادة الفتح.
- يمنع تعديل `created_at` و`created_by` و`created_by_name` من المتصفح.

**سياسات RLS:**

- `select`: كل مستخدم `authenticated`.
- `insert`: المستخدم الحالي فقط، مع `created_by = auth.uid()`.
- `update` / `delete`: أعضاء الفريق المسجّلون (ملاحظات مشتركة).
- `anon`: ممنوع تمامًا.

## الأمان

- استخدم فقط **Project URL** و**anon / publishable key** العامّين.
- لا ترفع ملفات `.env` أو أي مفاتيح سرية.
- راجع سياسات RLS بعد أي تغيير على الجدول.
- أوقف التسجيل العام بعد إنشاء حسابات الفريق.
- إن كان الوصول مطلوبًا لفريق محدد فقط، أضف طبقة عضوية/قائمة سماح فوق RLS (مثل جدول `team_members`) واربط السياسات به.

## استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| «جدول notes غير موجود» | نفّذ `supabase/schema.sql` في SQL Editor. |
| «لم تُضبط إعدادات Supabase» | املأ `assets/js/supabase-config.js` بـ URL و anon key. |
| «تعذّر تحميل مكتبة Supabase» | تحقق من الإنترنت أو حاجب CDN، ثم أعد تحميل الصفحة. |
| «البريد أو كلمة المرور غير صحيحة» | تحقق من الحساب أو أنشئ حسابًا جديدًا. |
| «لم يتم تأكيد البريد» | افتح رابط التأكيد المرسل إلى بريدك، أو عطّل تأكيد البريد مؤقتًا من إعدادات Auth. |
| لا تظهر تحديثات الفريق مباشرة | تحقق من إضافة `notes` إلى `supabase_realtime`، أو استخدم زر التحديث. |
| الصفحة تعمل من `file://` فقط | شغّل سيرفرًا محليًا (python أو Live Server) لتعمل المصادقة. |

## ملاحظات

- لا يستخدم التطبيق `localStorage` لتخزين الملاحظات إطلاقًا.
- وضع `?demo=1` مخصص للعرض والاختبار فقط، وليس بديلًا عن قاعدة البيانات.
- الواجهة متجاوبة مع الجوال واللوحي وسطح المكتب، وتدعم الطباعة الأساسية للسجل.
