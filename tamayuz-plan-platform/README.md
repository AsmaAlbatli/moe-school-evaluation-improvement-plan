# منصة تفريغ خطة التحسين في منصة تميز

منصة عربية (RTL) لتفريغ خطة التحسين وفق منصة تميز الرقمية، بهوية خضراء رسمية،
وبناء كامل من المجال ← المعيار ← المؤشر ← بيانات الخطة، مع المراجعة والإقرار
والطباعة والتصدير.

**تصميم المشرفة أسماء الباتلي**

---

## أبرز المزايا

- **بناء الخطة:** اختيار المجال والمعيار والمؤشر، ثم تعبئة الاحتياج وإجراءات
  التحسين وآليات التنفيذ والمسؤولية والمدة والدرجات.
- **توليد سريع:** لصق نص تقرير التقويم أو إدخال الدرجات مباشرة، ثم توليد الخطط
  للمؤشرات المحددة أو لما دون التميز.
- **استيراد تقارير PDF:** قراءة محلية على الجهاز، مع دعم الملفات النصية
  والملفات المصوّرة عبر التعرّف الضوئي (OCR) بالعربية والإنجليزية.
  إذا كانت جميع صفوف البطاقة المصوّرة سليمة تُعتمد درجاتها تلقائيًا، مع بيان
  المؤشرات التي لم ترد في البطاقة لتبقى فارغة بدل تخمينها.
  يدعم أيضًا تقارير **التقويم الخارجي 2025** ذات عمود الرمز/الدرجة/المستوى
  على يمين الصفحة، ويحوّل رموزها إلى بنك مؤشرات المنصة تلقائيًا.
  كما يقرأ **تقارير التقويم الذاتي** التي تعرض المؤشر والدرجة والمستوى الحالي
  دون رموز، ويطابق عناوين المؤشرات ببنك المنصة ثم يعتمد الدرجات.
- **المراجعة والإقرار:** مراجعة الخطط، الإقرار، والتوقيع.
- **ملاحظات سحابية:** إضافة وتعديل وحذف ملاحظات شخصية بعد تسجيل الدخول،
  محفوظة في Supabase ومحمية بسياسات RLS.
- **الطباعة والتصدير:** طباعة منسّقة، طباعة النموذج الفارغ، وتصدير Word.
- **النسخ الاحتياطي:** تصدير واستعادة نسخة JSON، وحفظ تلقائي سحابي بعد الدخول.
- **قائمة منسدلة مفعّلة:** تنقّل سريع وإجراءات (حفظ، طباعة، تصدير، نسخة
  احتياطية، استعادة، مسح) مع دعم لوحة المفاتيح.
- **إعدادات الهوية:** شعار المدرسة، بياناتها، ومظهر الهوية الخضراء.

## التشغيل

### الطريقة الأولى — سيرفر محلي (موصى به)

شغّل `تشغيل المنصة.bat` ثم افتح:

`http://127.0.0.1:8792/index.html`

### الطريقة الثانية — فتح مباشر

افتح `index.html` بالنقر المزدوج. تعمل معظم المزايا مباشرة، لكن استيراد PDF
والتعرّف الضوئي يحتاجان التشغيل عبر سيرفر محلي لقيود أمان المتصفح.

> **الخصوصية:** قراءة تقارير PDF ومعالجتها تتم داخل المتصفح، ولا تُرفع ملفات
> التقارير إلى أي خادم. أما بيانات الخطة والملاحظات فتُحفظ في حسابك على
> Supabase عند تسجيل الدخول، ولا يراها مستخدم آخر بفضل RLS. في وضع الزائر
> تبقى البيانات في الذاكرة فقط ولا تُحفظ بعد إغلاق الصفحة.
>
> **تسجيل الدخول** يحتاج تشغيل الصفحة عبر `http://` أو `https://` (مثل GitHub
> Pages أو السيرفر المحلي)؛ لا تستخدم `file://` مع Supabase لأن عناوين
> إعادة التوجيه وملفات تعريف الارتباط الأمنية تحتاج أصلًا (origin) صالحًا.

## المتطلبات

- متصفح حديث (Chrome أو Edge أو Firefox أو Safari).

## إعداد الحساب السحابي (Supabase)

المنصة تستخدم Supabase Auth لحساب كل مستخدم، وSupabase Database لحفظ مساحة
العمل والملاحظات. لا تعمل الحماية بالاعتماد على إخفاء المفتاح؛ بل بسياسات
**RLS** التي تربط كل صف بـ `auth.uid()`.

### 1) إنشاء الجداول

1. افتح مشروعك في [Supabase](https://supabase.com/dashboard).
2. اذهب إلى **SQL Editor**.
3. انسخ محتوى `supabase/schema.sql` كاملًا والصقه ثم اضغط **Run**.

السكربت ينشئ:

- `public.tamayuz_workspaces`: صف واحد لكل مستخدم يحتوي حالة الخطة كـ `jsonb`.
- `public.tamayuz_notes`: ملاحظات المستخدم (إضافة/تعديل/حذف).
- الفهارس، ومشغّل `updated_at`، وسياسات RLS للقراءة والإضافة والتعديل والحذف.
- منع دور `anon`، ومنح الصلاحيات للمستخدمين المسجّلين فقط.

### 2) إعدادات الدخول

في **Authentication ← Providers ← Email**:

- فعّل تسجيل الدخول بالبريد وكلمة المرور.
- للتجربة السريعة يمكن تعطيل **Confirm email**، أما الإنتاج فيُفضّل تفعيله.
- في **Authentication ← URL Configuration** أضف رابط النشر، مثل:
  `https://asmaalbatli.github.io/moe-school-evaluation-improvement-plan/tamayuz-plan-platform/index.html`
  إلى **Site URL** و**Redirect URLs**.

### 3) إضافة Project URL والمفتاح العام

افتح `index.html` وابحث عن بداية كتلة الإعداد:

```js
window.TAMAYUZ_SUPABASE = Object.assign({
  url: '',
  anonKey: ''
}, window.TAMAYUZ_SUPABASE || {});
```

- `url`: من **Project Settings ← API ← Project URL**.
- `anonKey`: المفتاح **anon public** أو **publishable** فقط.

> **تحذير أمني:** لا تضع `service_role` أو `sb_secret_...` في `index.html`
> أو في أي ملف يصل إلى المتصفح. مفتاح `anon` عام بطبيعته، لكن RLS هي التي
> تمنع المستخدم من الوصول إلى بيانات غيره. ملفات الأسرار المحلية مثل `.env`
> وملفات API الآمنة لا تُرفع إلى Git ولا إلى GitHub Pages.

### 4) طريقة العمل

- عند فتح المنصة بدون تسجيل دخول: تعمل في **وضع الزائر**، ولا تُحفظ التغييرات
  بعد إغلاق الصفحة بعد تفعيل Supabase.
- إذا لم تُضف إعدادات Supabase بعد، فتعمل المنصة في **وضع محلي مؤقت** وتحفظ
  بياناتها في `localStorage` تحت مفتاح الترحيل نفسه؛ وعند إضافة الإعدادات
  وتسجيل الدخول تُنقل البيانات تلقائيًا ثم يُحذف المفتاح المحلي.
- بعد تسجيل الدخول: تُجلب مساحة العمل من Supabase، ويُحفظ كل تعديل تلقائيًا
  بعد مهلة قصيرة. زر **«حسابي»** يعرض البريد وتسجيل الخروج.
- **ملاحظاتي**: نافذة لإضافة الملاحظات وتعديلها وحذفها، وكل عملية تُنفّذ على
  جدول `tamayuz_notes` ضمن صلاحيات المستخدم.
- **نسيت كلمة المرور؟**: يرسل Supabase رابطًا إلى البريد. عند فتح الرابط تظهر
  نافذة لتعيين كلمة مرور جديدة، ثم يتابع المستخدم داخل حسابه.
- عند أول دخول إن لم يكن هناك حفظ سحابي، تُرفع حالة الجلسة الحالية. وإن وُجد
  حفظ محلي قديم من النسخة السابقة (`tamayuz_plan_asmaa_v1`) ولم توجد بيانات
  سحابية، يُنقل تلقائيًا مرة واحدة. وإذا وُجدت بيانات سحابية تُعتمد هي. في
  الحالتين يُحذف المفتاح المحلي القديم بعد نجاح الدخول حتى لا ينتقل إلى حساب
  آخر على الجهاز نفسه.
- **مسح جميع البيانات** يحذف مساحة العمل والملاحظات السحابية للحساب الحالي.

## ملاحظات

- لا يُستخدم `localStorage` كوسيلة حفظ أساسية لبيانات المنصة؛ الحفظ الفعلي في
  Supabase. عند غياب إعدادات Supabase فقط يعمل وضع محلي مؤقت تحت مفتاح الترحيل
  نفسه، وعند التفعيل تُنقل البيانات ثم يُحذف المفتاح.
- ألوان مستويات الأداء (أحمر/برتقالي/أزرق/أخضر) محفوظة لدلالتها على المستوى.
- الهوية الأساسية: الأخضر السعودي `#006c35` مع تدرّجات خضراء داكنة ولمسات نعناعية.
- اسم المصممة في التذييل والقائمة مكتوب بخط الرقعة (Aref Ruqaa) بحجم أصغر،
  والخط مضمّن محليًا ليعمل دون اتصال.
